# v0.2.0 Supervisor Reporting Plan

## Objective

v0.2.0 starts the post-stabilization development cycle. The first deliverable is a Supervisor rollout report that shows where `.codex/supervisor.json` is already managed, missing, foreign, or invalid across registered project candidates.

## Scope

- Add Supervisor status inspection for each registered project candidate.
- Add aggregate report counts for `Managed`, `Missing`, `Foreign`, and `Invalid`.
- Add a startup menu action for the report.
- Add a pre-apply diff preview when an existing supervisor manifest will be updated.
- Keep Supervisor rollout as numbered selection.
- Keep release, merge, and public visibility decisions with the human owner.

## Report Statuses

| Status | Meaning |
|---|---|
| `Managed` | `.codex/supervisor.json` exists, is managed by this tool, `codexOnly=true`, and `sshEnabled=false`. |
| `Missing` | `.codex/supervisor.json` does not exist. |
| `Foreign` | A supervisor file exists, but it is not recognized as this tool's managed Linux Codex supervisor manifest. |
| `Invalid` | A supervisor file exists, but it cannot be parsed as JSON. |

## Diff Preview Actions

| Action | Meaning |
|---|---|
| `Create` | No existing supervisor manifest; a new one will be written. |
| `Update` | Existing manifest is valid JSON, but policy fields differ. |
| `ReplaceInvalid` | Existing manifest cannot be parsed and will be replaced after confirmation. |
| `RefreshTimestamp` | Policy fields already match; only `supervisorAppliedAt` will refresh. |

## Verification

Required before human release judgment:

- Pester unit tests pass.
- ArchitectureCheck passes.
- `Start-Codex.ps1 -DryRun -NonInteractive` passes.
- GitHub Actions CI passes on the pushed development branch.
- README documents the report workflow and safety gates.

## Out of Scope

- Final release tag creation.
- GitHub Release publication.
- Repository publicization.
- Broad `all` rollout.
