# v0.2.0 Release Notes

## Objective

v0.2.0 completes the post-stabilization development cycle. The release adds Supervisor rollout reporting, safer update previews, project candidate management, release readiness checks, GitHub PR confirmation, and recent-project Codex restart.

## Scope

- Add Supervisor status inspection for each registered project candidate.
- Add aggregate report counts for `Managed`, `Missing`, `Foreign`, and `Invalid`.
- Add a startup menu action for the report.
- Add a pre-apply diff preview when an existing supervisor manifest will be updated.
- Add a registered project candidate management UI for exclusions and categories.
- Add an integrated pre-release check command.
- Add a GitHub PR creation/confirmation flow.
- Add recent-project Codex restart from numbered history selection.
- Keep Supervisor rollout as numbered selection.
- Keep release, merge, and public visibility decisions with the human owner.

## Report Statuses

| Status | Meaning |
|---|---|
| `Managed` | `.codex/supervisor.json` exists, is managed by this tool, `codexOnly=true`, and `sshEnabled=false`. |
| `Missing` | `.codex/supervisor.json` does not exist. |
| `Foreign` | A supervisor file exists, but it is not recognized as this tool's managed Linux Codex supervisor manifest. |
| `Invalid` | A supervisor file exists, but it cannot be parsed as JSON. |

## Diff Preview Actions

| Action | Meaning |
|---|---|
| `Create` | No existing supervisor manifest; a new one will be written. |
| `Update` | Existing manifest is valid JSON, but policy fields differ. |
| `ReplaceInvalid` | Existing manifest cannot be parsed and will be replaced after confirmation. |
| `RefreshTimestamp` | Policy fields already match; only `supervisorAppliedAt` will refresh. |

## Project Candidate Management UI

Menu item `11. プロジェクト候補管理` lists registered project candidates including excluded projects. Operators can update `config/config.json` with number-based commands:

| Input | Operation |
|---|---|
| `+1,3` | Add selected projects to `registeredProjects.exclude`. |
| `-2` | Remove selected projects from `registeredProjects.exclude`. |
| `c1,3:startup-tools` | Assign selected projects to `registeredProjects.categories.startup-tools`. |
| `0` | Return without changes. |

## Integrated Pre-Release Check

Command:

```bash
pwsh -NoProfile -File scripts/main/Invoke-ReleaseCheck.ps1
```

The command checks:

- Git worktree cleanliness.
- Runtime paths ignored by Git.
- README release documentation.
- Linux default config template and schema validity.
- Pester unit tests.
- Codex dry-run.
- ArchitectureCheck.

During development only, `-AllowDirty` can be used for a provisional run. Final release judgment should run without `-AllowDirty`.

## GitHub PR Flow

Command:

```bash
pwsh -NoProfile -File scripts/main/Invoke-GitHubPrFlow.ps1
```

Default behavior is confirmation-only. Draft PR creation requires explicit `-CreateDraft`.

The flow checks:

- `gh` CLI availability.
- `gh auth` status.
- Current branch is not `main`, `master`, or `develop`.
- Origin is a GitHub repository.
- Existing PR metadata.
- PR check rollup.

Safety rules:

- Existing PRs are not duplicated.
- Newly created PRs are draft PRs.
- Merge, release, and public visibility remain human decisions.

## Recent Project Restart

Menu item `7. 最近のプロジェクト再起動` reads `recentProjects.historyFile`, filters Codex local launch history, removes duplicate project entries by keeping the newest entry, and shows numbered restart candidates.

Candidate states:

| State | Meaning |
|---|---|
| `ready` | The project directory exists under `projectsDir` and can be restarted. |
| `missing` | The project is in history, but its directory is not currently present. |

Restart behavior:

- Number selection is required.
- `0` cancels and returns to the menu.
- Missing projects are not launched.
- Ready projects are restarted through `scripts/main/Start-Codex.ps1 -Project <name>`.
- Repository visibility is not changed.

## Verification

Required before human release judgment:

- Pester unit tests pass.
- ArchitectureCheck passes.
- `Start-Codex.ps1 -DryRun -NonInteractive` passes.
- Recent-project restart helper tests pass.
- GitHub Actions CI passes on the pushed development branch.
- README documents the report workflow and safety gates.
